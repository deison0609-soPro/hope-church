# 希望教會官網 —— 內容更新手冊

給多媒體同工使用｜不需要會寫程式，跟著步驟做就好

---

## 開始之前：請 E 哥先幫你做這件事

1. E 哥登入 GitHub → 打開 https://github.com/deison0609-soPro/hope-church
2. 點 **Settings** → 左側 **Collaborators** → **Add people**
3. 輸入你的 GitHub 帳號或 Email，送出邀請
4. 你會收到一封邀請信，點裡面的連結接受邀請
5. 之後註冊/登入一個免費的 GitHub 帳號（如果還沒有）：https://github.com/signup

完成後，你就可以照下面的步驟編輯網站內容了。

---

## 🔒 安全規則（一定要遵守）

**不要直接在 `main` 分支上修改！**
請照下面步驟，先建立一個新分支（branch）再編輯。這樣就算格式寫錯，也**不會讓網站掛掉**——Cloudflare 會先給一個「預覽連結」讓 E 哥確認沒問題，才會正式上線。

## 任務 A：新增本週「主日信息」

### Step 1：建立新分支

1. 打開 repo：https://github.com/deison0609-soPro/hope-church
2. 左上角有個顯示 `main` 的下拉選單，點開
3. 直接打上新的分支名稱，例如：`update-0222-message`
4. 點 **Create branch: update-0222-message from 'main'**

### Step 2：上傳本週的圖卡（凱西做的正方形圖）

1. 進到資料夾：`public/images/messages/`
2. 點右上角 **Add file** → **Upload files**
3. 把圖片拖曳進去，檔名建議跟日期一致，例如 `2026-02-22-新標題.jpg`
4. 下方 **Commit changes** 前，記得選 **「Commit directly to the update-0222-message branch」**
5. 點 **Commit changes**

### Step 3：新增文章檔案

1. 進到資料夾：`src/content/messages/`
2. 點 **Add file** → **Create new file**
3. 檔名輸入：`2026-02-22-新標題.md`（日期-標題，用英文或拼音都可以）
4. 貼上以下內容，把 `___` 換成實際資料：

```yaml
---
title: ___這週的標題___
date: "2026-02-22"
description: ___一句話摘要___
scripture: ___出處章節（例如：約翰福音 3：16）___
youtube: ___YouTube 影片連結（文泰給的）___
cover: /images/messages/2026-02-22-新標題.jpg
---

這裡開始寫這週的信息內容。

## 可以這樣分段

一般文字直接打就好。

> 這樣寫會變成醒目的引言框，適合放經文或重點。
```

5. 一樣選 **Commit directly to the update-0222-message branch**，點 **Commit changes**

### Step 4：開 Pull Request（請 E 哥確認）

1. 上傳完後，頁面上方會出現黃色提示條，點 **Compare & pull request**
2. 標題隨便打（例如：「新增 2/22 主日信息」）
3. 點 **Create pull request**
4. 等 1-2 分鐘，下方會出現 Cloudflare 產生的 **預覽連結**，點開檢查畫面對不對
5. 通知 E 哥來確認，沒問題他會按 **Merge**，正式上線（約 1 分鐘後生效）

## 任務 B：新增「最新消息」（活動公告）

跟任務 A 完全一樣的流程，只差兩個地方：

- 圖片放到：`public/images/news/`（不是 `messages`）
- 文章檔案放到：`src/content/news/`，frontmatter 改用：

```yaml
---
title: ___活動標題___
date: "2026-02-22"
description: ___一句話摘要___
cover: /images/news/2026-02-22-活動名稱.jpg
signupForm: true   ← 只有「需要在網站上直接填表單報名」的活動才加這行，否則整行刪掉
---

活動內容...
```

---

## 常見錯誤，請小心

| 錯誤 | 後果 | 怎麼避免 |
|------|------|---------|
| 日期沒加引號，寫成 `date: 2026-02-22` | 建置失敗，網站掛掉 | 一定要寫成 `date: "2026-02-22"`（有引號） |
| 忘記檔案開頭/結尾的 `---` | 建置失敗 | 複製上面模板時，連 `---` 一起複製，不要漏 |
| 圖片路徑打錯（少打 `/images/...` 開頭） | 圖片顯示不出來 | 路徑一定從 `/images/` 開始 |
| 直接在 `main` 分支修改 | 沒有預覽機會，出錯直接影響正式網站 | 一定要先建分支，走 Pull Request |

## 有問題怎麼辦？

- 不確定某個步驟 → 截圖傳給 E 哥
- Pull Request 的預覽連結畫面跑版 → 先不要按 Merge，通知 E 哥看
- 想要更輕鬆的編輯方式（填表單就好，不用碰程式碼）→ 跟 E 哥反應，未來會評估架設更友善的編輯後台（Decap CMS）
